# Booking assistant: implementation plan

Companion to [booking-assistant.md](./booking-assistant.md). The feature was first committed in `46a3dc9`; this plan covers verifying it against the spec and finishing it.

## Phase 1: Backend check

- Compare `packages/services/src/assistant.ts` and `assistant.test.ts` with the spec.
  - `createAssistantService(db, parseSlot)` takes the parser as a parameter and never reads `env`.
  - `suggest` re-parses its input with zod, validates the model output, and reuses `availability.freeRooms`.
  - A missing time, an end before the start, or garbage output returns `ok: false`.
  - A throwing parser returns "The assistant couldn't understand that. Try again or use the form."
- Tests cover: a booked room is excluded, a room under the attendee count is excluded, the three failure cases, and a throwing parser.
- Check the wiring: `assistant-model.ts` is the only code touching `env.AI`, `context.ts` builds `parseSlot` from `bindings.AI`, the router is thin, and `router.ts` registers it.
- Check `wrangler.jsonc` has the `ai` binding and `worker-configuration.d.ts` was generated by `bun run cf-typegen`.
- Run `bun test packages/services/src/assistant.test.ts`.

## Phase 2: UI and layering check

- `AssistantBox.tsx`, `bookings.tsx` and `BookingForm.tsx`:
  - Browser code imports only `@repo/db/shared`.
  - Picking a room sets room and day through `navigate`, and prefills start, end and attendees.
  - The member still submits the form, so existing validation and the daily limit apply.
  - Errors show through `FormError`, and the empty state shows the parsed slot.
- Run `bun run check` and fix what it reports.

## Phase 3: Manual run and write-up

- `bun run dev` (Workers AI needs `wrangler login` and may incur usage). Try "room for 4 tomorrow 10-11", click a room, submit; then try an unparseable request.
- Mark the spec as done and note the Workers AI login requirement in the PR description.
